# AI100P 设计文档

- **产品名**：AI100P
- **当前版本**：V1（2026-09）
- **形态**：静态精选导览站 + 周更数据流水线
- **一句话**：一份克制而完整的 2026 年全球热门 100 款 AI 产品地图，按分类陈列、按周刷新资讯，名单以稳为主。

---

## 1. 产品定位

AI100P 是面向普通用户与从业者的 **学习与信息展示** 产品，不是评测站、不是投资建议、也不是全网第 1–100 的实时排行榜。

用户打开站点，应能在几分钟内建立对当下 AI 应用生态的整体认知：有哪些赛道、每条赛道有哪些值得关注的产品、各自做什么、怎么定价、最近有什么动态。

### 1.1 要解决的问题

市场上 AI 产品极多、更新极快。用户需要的不是每天刷新的热度榜，而是：

1. 一份 **数量固定、结构稳定** 的百款地图，避免信息过载。
2. 按「我想做什么」而不是按名次浏览。
3. 点开一款产品，能看到定位、能力标签、定价、里程碑和本周资讯。
4. 名单会缓慢代谢，但不会因为一周的热搜而整页洗牌。

### 1.2 明确不做（非目标）

| 不做 | 原因 |
|------|------|
| 公开名次、热度分、升降箭头 | 小幅数据波动会逼着每周改版，损害信任 |
| 实时榜 / 日更榜 | 用户要的是隔几天到一周的「还算新」，不是秒级 |
| 模型评测、基准跑分 | 那是 LMSYS、Artificial Analysis 的事 |
| 投资、购买建议 | 页脚免责声明已写明 |
| 用户账号、社区、投稿 | V1 是只读导览 |
| 自动改写卡片定价与时间线 | 媒体传闻不可靠；时间线只认官方，V1 仍人工维护 |

### 1.3 成功标准（V1）

一周之后用户应看到：

- 产品详情里的 **本周资讯** 有更新。
- ChatGPT、豆包等头部产品仍在。
- 观察档至多小步换人（每周最多 3 个、同分类 1 换 1）；**0 次自动替换也算成功**——说明名单该稳。
- 更大变动只出现在「建议换人清单」，不静默改靠前档。

## 2. 用户与场景

| 角色 | 场景 | 关键路径 |
|------|------|----------|
| 普通用户 | 「现在 AI 都能干什么」 | Hero → 赛道入口 → 扫卡片 → 点开详情 → 访问官网 |
| 从业者 / 产品经理 | 对标某条赛道 | 12 分类浏览或搜索公司名 / 产品名 |
| 开发者 | 找编程或 Agent 工具 | 切到 6 大赛道「编程开发」，或搜索 IDE |
| 维护者（自己） | 每周让名单和资讯不过时 | `npm run update:weekly`，再看 `roster.html` 决定要不要人工改靠前档 |

默认语言是中文。英文只翻译 **界面、分类名、赛道名**；产品介绍、tagline、时间线保持中文原文，避免机翻损伤专有名词。

## 3. 信息架构

两页，无登录。

```
首页 index.html
 ├─ 顶栏：品牌 · 分类锚点 · 搜索 · 中英切换 · 移动端抽屉
 ├─ Hero：定位文案 + 漂浮产品徽标
 ├─ 统计条：100 款 / 12 类 / 生成式占比 / 可免费体验
 ├─ 6 条任务赛道（快捷入口）
 ├─ 工具栏：12 细分 ↔ 6 大赛道 · 分类 · 定价 · 计数
 ├─ 主列表：分类横幅 + 产品卡片网格
 ├─ 详情弹窗：介绍 · 时间线 · 本周资讯 · 官网
 └─ 页脚：分类索引 · 免责 · 选品更新入口

选品页 roster.html
 ├─ 本周自动替换
 └─ 建议换人清单（人工决策用）
```

### 3.1 双视角分组

同一份 100 款名单，两种切法，不复制数据。

**12 细分分类**（默认）——按产品形态：

| ID | 中文 | 席位 | 生成式 |
|----|------|------|--------|
| `chat` | 对话式 AI | 9 | 是 |
| `coding` | AI 编程 | 9 | 否 |
| `image` | 图像生成 | 9 | 是 |
| `video` | 视频生成 | 9 | 是 |
| `audio` | 音频语音 | 9 | 是 |
| `search` | AI 搜索 | 8 | 否 |
| `writing` | AI 写作 | 8 | 是 |
| `office` | AI 办公 | 7 | 否 |
| `design` | AI 设计 | 8 | 是 |
| `agent` | AI 智能体 | 8 | 否 |
| `companion` | AI 陪伴 | 8 | 否 |
| `vertical` | 垂直行业 | 8 | 否 |

席位按分类配额固定，合计 100。某一类要加人，必须同分类 1 换 1，总量不变。

**6 大赛道**——按「用户想做什么」把 12 类两两归并：

| 赛道 | 包含分类 |
|------|----------|
| 对话 · 搜索 · 问答 | chat + search |
| 图像 · 视频 · 视觉创作 | image + video |
| 写作 · 音频 · 内容创作 | writing + audio |
| 编程 · 开发 · 智能体 | coding + agent |
| 办公 · 设计 · 生产力 | office + design |
| 陪伴 · 垂直行业 | companion + vertical |

切到 6 赛道时，每个赛道内部仍按原分类分子标题，避免把 ChatGPT 和 Perplexity 混成一排无法区分。

### 3.2 产品卡片与详情

卡片只承担「扫一眼」：Logo、名称、公司、一句话定位、最多 3 个能力标签、定价、所属分类。

详情弹窗承担「决定要不要点官网」：

1. 完整介绍
2. 版本与里程碑（人工维护，日期以官网为准）
3. 本周资讯（周更缓存优先；没有缓存时再尝试 HN）
4. 定价 / 分类 / 公司
5. 访问官网

页面 **不展示** 内部档位（靠前 / 中间 / 观察）、不展示分数、不展示名次。档位只用于排序和换人策略。

### 3.3 筛选

- 分组：12 细分 / 6 大赛道
- 分类：当前视角下的分组芯片
- 定价：全部 / 免费 / 订阅 / 开源 / 企业（子串匹配卡片上的定价文案）
- 搜索：名称、公司、定位、介绍、别名、标签、分类简称

有筛选时，主列表换成匹配网格；无匹配给出空状态，可点「全部」重置。

## 4. 视觉与交互

### 4.1 设计原则

CSS 注释中的方案名是 **「东方雅致」**：纸色底、墨绿主色、克制的朱红点缀。不追求赛博霓虹，避免「又一个 AI 落地页」的廉价感。

兼容性优先：不使用 `color-mix()` 等新语法，颜色用预计算 CSS 变量。

### 4.2 设计 token

| Token | 值 | 用途 |
|-------|-----|------|
| `--bg` | `#FAFAF8` | 纸白背景 |
| `--bg-2` | `#F3F2EC` | 浅米分层 |
| `--ink` | `#1A1A1A` | 主文字 |
| `--muted` | `#73736C` | 说明文字 |
| `--primary` | `#2E6E6A` | 品牌绿、高亮、主按钮 |
| `--accent` | `#C0392B` | 点缀红（品牌标右下点、渐变字） |
| `--radius` | `16px` | 卡片圆角 |
| `--maxw` | `1220px` | 内容宽度 |
| 字体 | Inter + 苹方 / 鸿蒙 / 思源 | 中英混排 |

每个分类另有独立 `accent`，用于分类横幅、圆点、卡片左边色。产品自身也有 `accent`，用于 Logo 底色回退。

品牌写法：`AI100P · 2026`，末尾 **P** 用主色高亮，对应 CSS `.brand b span`。

### 4.3 动效与无障碍

- Hero 背景随机撒产品徽标，缓慢漂浮；数量随视口变化（约 14 / 22 / 34）。
- 统计数字进入视口后计数动画。
- 分类横幅滚入渐现。
- 顶栏滚动后变实心毛玻璃；进度条贴顶。
- 尊重 `prefers-reduced-motion`：减弱漂浮、取消计数动画、滚动改为瞬间跳转。
- 卡片可键盘聚焦，Enter / 空格打开详情；弹窗 Escape 关闭并还回焦点。
- Logo 加载失败时显示字母徽标，不留破图。

### 4.4 响应式

| 断点 | 行为 |
|------|------|
| ≤980px | 隐藏顶部分类链接，改用抽屉菜单 |
| ≤880px | 赛道入口两列 |
| ≤680px | 卡片与 Hero 收紧 |
| ≥760px | 详情弹窗居中卡片，而不是贴底 |

## 5. 选品方法论

这是产品的核心编辑策略，也是自动换人必须遵守的边界。

### 5.1 三档，只对内

| 档位 | 代码 | 含义 | 更新节奏 | 页面表现 |
|------|------|------|----------|----------|
| 靠前 | `lead` | 该分类的锚定产品，无故不出局 | 季度级，人工 | 排在分类最前，无标签 |
| 中间 | `core` | 有规模、有动量，可按月审视 | 月级，V1 仍人工 | 紧随靠前，无标签 |
| 观察 | `watch` | 新、小、或信号不稳 | 周级，可自动 1 换 1 | 排在分类最后，无标签 |

同档之内用 `seed` 保持稳定顺序，避免每次构建都重排。当前配额约 **37 / 45 / 18**。

规模信号参考 AICPB、QuestMobile、Similarweb 等 **公开榜单的方向**，不转载完整数字，也不把这些分数画到页面上。

### 5.2 全球名品与中国产品并存

每个分类按「全球现象级 + 中国用户真正在用」混编，而不是按英文搜索热度堆满硅谷产品。国内月活很高、但暂时不便自动写入的产品（如夸克、腾讯元宝）放在 `data/bench.json` 备选池，**只进建议清单**。

### 5.3 自动换人：宁可错过，不要误换

无人值守时只动观察档。硬规则：

1. 只替换 `watch`；`lead` / `core` 永远只出现在建议清单。
2. 同分类 1 换 1，总量仍为 100。
3. 每周最多 3 次自动替换。
4. 同一分类 21 天冷却，避免来回抖。
5. 候选必须能推断分类、有可访问官网、名称像独立产品。
6. 本应进靠前/中间档的候选（`desiredTier !== watch`，或 `autoEligible === false`）**绝不静默塞进观察档**。
7. 必须同时满足「在任观察档连续偏弱」和「候选明显更强」：
   - **强信号**：候选来自备选池或 Product Hunt，分 ≥ 18，且在任分 ≤ 2、至少安静 1 周。
   - **慢信号**：在任安静 ≥ 2 周且分 ≤ 3，候选分 ≥ 14 且至少是在任的 3 倍。

不满足则本周名单不动。被换下的产品写入 `data/alumni.json`，便于日后回溯。

### 5.4 建议换人清单

`roster.html` 给维护者看，不面向普通浏览路径的主流程。典型建议包括：

- 夸克应进搜索靠前档，不能塞观察档。
- 腾讯元宝应进对话靠前档；该分类甚至没有观察席，不能无人值守换人。
- 某观察档已连续无资讯，下周若出现强信号新品再自动换。

### 5.5 明确不用作主源的榜单

LMSYS Arena、Artificial Analysis、CB Insights AI 100、Sequoia AI 50、There's An AI For That、Toolify、SeekTool 等：可以交叉看看，**不能单独决定入选**。原因：评测榜偏模型、榜单站偏目录堆量，和「用户真正在用的产品」不是同一件事。

## 6. 数据模型

源数据在 `/data`，构建后打成 `js/data.js` 里的 `CATALOG`，页面运行时只读这一份。

### 6.1 产品卡片 `products.json`

```json
{
  "id": "chatgpt",
  "name": "ChatGPT",
  "company": "OpenAI",
  "cat": "chat",
  "abbr": "GPT",
  "accent": "#10A37F",
  "pricing": "免费 + 订阅",
  "url": "https://chat.openai.com",
  "tagline": "全球访问量最高的通用 AI 助手",
  "tags": ["写作", "编程", "多模态"],
  "intro": "……",
  "tier": "lead",
  "seed": 0,
  "aliases": ["ChatGPT", "OpenAI"],
  "rss": ["https://openai.com/news/rss.xml"]
}
```

| 字段 | 作用 |
|------|------|
| `id` | 稳定主键，资讯、时间线、换人状态都靠它 |
| `abbr` | Logo 失败时的字母 / 汉字徽标 |
| `aliases` | 搜索与资讯标题匹配；公司名过泛的会从匹配里剔除，避免「OpenAI」把所有子产品串味 |
| `rss` | 官方动态源；没有则走 Google News / HN / 中文媒体 |
| `tier` / `seed` | 仅内部排序 |
| `addedAt` / `addedBy` | 自动换人写入时标记来源 |

### 6.2 其他数据文件

| 文件 | 职责 |
|------|------|
| `categories.json` | 12 分类文案、中英、是否生成式、色值 |
| `tracks.json` | 6 赛道及成员分类 |
| `timelines.json` | `id → [[日期, 事件], …]` |
| `news.json` | 周更资讯缓存，每款最多 5 条 |
| `sources.json` | 资讯与名单的来源政策（给人看的规则书） |
| `bench.json` | 高置信备选，默认不允许自动进入 |
| `alumni.json` | 被换下的历史卡片 |
| `roster-state.json` | 安静周数、分类冷却、已执行替换 |
| `roster-report.json` | 最近一次换人报告，供生成 `roster.html` |
| `meta.json` | 标题、更新日期、档位计数 |

## 7. 更新机制

### 7.1 周更流水线

```
npm run update:weekly
  ├─ scripts/update-news.mjs     抓近 14 天资讯 → data/news.json
  ├─ scripts/update-roster.mjs   观察档换人 / 写建议 → products + roster.html
  └─ scripts/build-data.mjs      汇总 JSON → js/data.js
```

入口脚本：`scripts/weekly.sh`（可加载本地 `.env`）。

### 7.2 资讯抓取

写入顺序：官方 RSS → Google News → Hacker News → 中文媒体（36氪、量子位）。

规则：

- 标题必须命中产品名或 aliases。
- 短英文名（如 Pi、Make）要额外上下文，降低误伤。
- 每款最多 5 条，按时间倒序去重。
- 媒体里的定价传闻 **只进资讯，不改卡片定价**。
- 时间线 **不由这套管线改写**。

详情弹窗优先渲染这份周更缓存；某款没有缓存时，打开弹窗再请求 HN Algolia 作为回退。

### 7.3 候选从哪来

1. `bench.json`（人工备选，通常不可自动进入）
2. Hacker News `Show HN`（近 14 天、分数门槛、能推断分类）
3. Product Hunt GraphQL（需 `PRODUCTHUNT_TOKEN`，观察档主源之一，仍不能单独决定入选）

### 7.4 定时

| 通道 | 时间 | 说明 |
|------|------|------|
| 本机 launchd | 每周一 10:00（本机时区） | `npm run schedule:install`，标签 `com.aibaixuan.weekly` |
| GitHub Actions | 每周一 10:00 北京时间 | `.github/workflows/weekly.yml`，自动 commit 数据文件 |

本机电脑关机则 launchd 不跑。云端无人值守需要仓库已推到 GitHub，并把 `PRODUCTHUNT_TOKEN` 配进 Actions secrets。

手跑：

```bash
npm start                 # 本地预览 http://127.0.0.1:4173
npm run update:weekly     # 真更新
npm run update:weekly -- --dry-run   # 只出建议，不改名单
```

改 JSON 后若只重建页面数据：`npm run build:data`。

## 8. 技术架构

无框架、无打包、无后端。浏览器直接打开静态文件。

```
index.html / roster.html
css/styles.css
js/data.js          ← build-data.mjs 生成，勿手改
js/app.js           ← 页面逻辑
data/*.json         ← 唯一事实来源
scripts/*.mjs       ← Node 18+ 流水线
```

- `build-data.mjs`：把分类、赛道、产品、时间线、来源、资讯、元数据打进 `CATALOG`。
- `compose-app.mjs`：从 `scripts/_logic-chunk.js` 拼出 `js/app.js`（维护界面文案时改 chunk，再 compose）。
- Logo：DuckDuckGo 站点图标 → Google Favicon → Clearbit，全失败显示 `abbr`。
- 中英切换时，若弹窗里出现英文 HN 标题，可用 MyMemory 做一次性翻译；失败则保留原文。

### 8.1 运行时状态（仅内存）

```
{ cat, price, q, mode }   // 分类 / 定价 / 搜索词 / 12|6
lang                      // zh | en
```

不写 localStorage。刷新即回到中文、12 分类、无筛选。这是有意的：导览站每次进入都应是同一张「地图」，而不是个性化首页。

## 9. 合规与展示边界

- 页脚写明：仅供学习与信息展示，不构成投资或购买建议。
- Logo、名称、商标归各公司所有；图标按官网域名经第三方服务加载，失败则字母占位。
- 具体能力与定价以各产品官网为准。
- 不展示爬到的完整访问量数字。
- `.env` 与 `PRODUCTHUNT_TOKEN` 不入库。
